# paperclip.front-bot-lookups

- Status: active
- Since: unreleased
- Source: HAL-19222 (v3 of the front bot design on HAL-18847: read-only Studio lookups, off by default; guard rails of sections 4 and 7)

When a board user's message on a chat task is in scope for the front bot, the front bot is on and its lookups setting `frontBotLookups` is `true`, and the message has no key shape and the chat's agent hasn't answered it, the Agent tools plugin shall answer it by itself only when the whole message, on one line of at most 120 characters, is one of the fixed PR status questions about one pull request (such as "Is #6129 merged?", "status of PR 6129") or run status questions about one task (such as "Is HAL-123 running?", "run status HAL-123"); it shall read the answer only from that lookup's read-only source, GitHub's pull request status on the company's first watched repository with GET requests only, or the task and its active run from Paperclip; it shall post the answer as a comment with no author, built only from fixed phrases filled in from that result and starting with `*Automatic answer · from PR status:* ` or `*Automatic answer · from run status:* `, keep its id on the front bot's own-comment list, treat any comment with no author that starts with `*Automatic answer · from ` as the bot's, and make no Haiku call for that message; it shall read nothing and answer nothing for a message holding a word that asks for an action (such as merge, queue, rebase, close, fix, please or "can you"), logging `write_request`, or for any other question; and when the source fails, gives nothing within 8 seconds, finds no such task, gives a result about another subject or a value with no fixed phrase, or the agent answered meanwhile, it shall post no answer, log `lookup_failed`, `lookup_not_found`, `lookup_mismatch`, `lookup_unreadable` or `agent_answered`, and leave the message to the first reply and the agent as before. With `frontBotLookups` or `frontBotEnabled` not `true`, it shall read no lookup source.

## Examples

- Given the lookups on and PR #6129 open with ci-ok green, no conflict, not queued and approved on its head, when a board user writes "Is #6129 merged?", then the plugin posts "*Automatic answer · from PR status:* PR #6129: open; ci-ok green; no conflict; not in the merge queue; approved on its latest commit." with no author.
- Given the lookups on and HAL-123 in progress with Liam's run running since 14:02, when a board user writes "Is HAL-123 running?", then the plugin posts "*Automatic answer · from run status:* HAL-123: in progress; Liam's run is under way, started 14:02 UTC.".
- Given the lookups on, when a board user writes "Please merge #6129", then the plugin reads no source, posts no answer and logs `write_request`.
- Given the lookups on and GitHub failing, when a board user writes "Is #6129 merged?", then the plugin posts no answer, logs `lookup_failed`, and the first reply runs as before.
- Given `frontBotLookups` off, when a board user writes "Is #6129 merged?", then the plugin reads no lookup source.
