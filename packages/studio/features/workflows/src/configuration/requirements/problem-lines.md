# workflows.configuration.problem-lines

- Status: draft
- Since: unreleased
- Source: HAL-9957 (T7 PR 4); HAL-413 (problem lines); flow-workflows 4.4; UX checklist 3.5; HAL-15120 (C544 finding 10: a new step's problems in the file's words); HAL-15140 (C544-3: a step by its name); HAL-15206 (a wait step's card and row both say answers); HAL-15540 (C592 3: an arrow that is never taken says so in the step card's words); HAL-15548 (C591 row 13 on HAL-15531: a never-taken arrow's row in Studio's words); HAL-15639 (C605 #3, a missing model alias in Studio's words); HAL-15732 (C622 #3: a wait step's signal, one name for a step's kind); HAL-15590 (C596 #4 on HAL-15586: a wait's arrow without an answer); HAL-16066 (C665 85 to 87: a wait's bare arrow is taken on Done)

When the checks find problems in a workflow, the workflows feature shall write each one as its glyph (✕ for an error, △ for a warning) and a short line of about 25 characters that starts with a capital and leaves out the step's name, list errors before warnings, and for several problems on one card say "✕ 2 problems" or "△ 2 warnings"; a problem of the whole workflow shall be a sentence, and a check with no written line shall show the core's own message. Configuration › Problems shall show, for every problem, followed by the step it links to, a sentence in Studio's words for the checks a newly added step gets (`task-without-agent`, `dead-end`, `unreachable`, `wait-without-events`), for an arrow that's never taken (`unguarded-shadow`) or has no answer at a wait (`wait-arrow-without-event`), and for a wait step's `signal` (`wait-with-signal`), which leaves out the step's name and says what to do, for `unknown-model-alias` when the host names the agent the problems band's line for it (`workflows.start.start-run`), which says "agent step" where the core says "Method", and the core's full message for the other checks. These lines and sentences shall call a step's kind "a wait step" or "an end step", as `halonic validate` and the no-end-step sentence do, not by the Type picker's labels. Wherever Studio names a step in a problem (the core's message and the row's link), it shall name it as its card on the canvas does: by its title, or by its id when it has none; `halonic validate` keeps the id, as the file uses it.

## Examples

- Given an `unguarded-shadow` warning, then its short line reads "Never taken", as the step card's arrow row says.
- Given a `dead-end` error on Review, then the card reads "✕ Has no way out"; the row on Configuration › Problems says "Has no way out. Add an arrow from it on its card, or make it an end step.", then links to Review.
- Given a new agent step `step-1`, then its rows say "Has no agent, so every run fails here. Pick one on its card, or make it a wait step." and "Can't be reached: no arrow leads to it.", not the core's `agent: <id>`.
- Given a wait step `wait-1` with a `signal`, then its card reads "✕ Can't send a signal" and its row says "Can't send a signal: a wait step has no moment to send one. Move the signal to the step after it, in the workflow's file.", not the core's message with the step's id.
- Given a `timer-outside-wait` error, then the card reads "✕ Only a wait step has timers".
- Given a new wait step `wait-1`, then its card reads "△ Has no answers to pick" and its row says "Gives a person no answers to pick, such as approve. Add them in the workflow's file.".
- Given an `unguarded-shadow` warning on Review, then its row says "Has an arrow that's never taken: an earlier arrow on the same event always matches first. Change the order or the conditions in Arrows on its card.", not the core's message with "transition".
- Given a `wait-arrow-without-event` warning on an arrow of the wait step Review, then its row says "Has an arrow with no answer, so it's taken only if someone answers Done. Give the arrow an answer, or a timer, in the workflow's file.", not the core's message with "transition"; the arrow's line is "Taken on Done", its plate's tooltip says "This arrow has no answer, so it's taken only if someone answers Done. Give it an answer, or a timer, in the workflow's file.", and Review's card doesn't show it.
- Given an `unknown-gets` error, then its row shows the core's full message.
- Given `unknown-model-alias` for Writer's agent step `short` and the alias `tiny`, then its row says "Writer's agent step short uses the model alias tiny, which this workspace doesn't have. Add it in Models." in place of `Method "writer.short" uses unknown model alias "tiny"`; for Writer's own `smrt`, "Writer uses the model alias smrt, which this workspace doesn't have. Pick a model on Writer's page.".
- Given the step `first`, titled "Ask a missing agent", uses the missing agent `nobody-here`, then its row says `"Ask a missing agent" uses the agent "nobody-here", which its hub doesn't have` and its link reads "Ask a missing agent"; a step with no title is named by its id in both.
- Given a warning and then an error, then the error row comes first.
- Given `no-final`, then the card line reads "This workflow has no end step."; the Problems row shows core's message and has no step link.
- Given two warnings on one card, then the card says "△ 2 warnings"; given a warning and an error, "✕ 2 problems".
- Given a check with no written line, then the card shows the core's message.
