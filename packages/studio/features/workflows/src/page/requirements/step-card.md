# workflows.page.step-card

- Status: active
- Since: unreleased
- Source: HAL-12216 (T7b PR 1b, 1c); UX checklist 10.8; flow-workflows 5.1, 5.2; microcopy 9.4; save model (HAL-1300 note, 8.4); a11y 7.2; C285 DK1, NA1 (HAL-14002); C544 finding 10 (HAL-15120: the title without "Step")

When a step is picked on the canvas on desktop, no run is shown and nothing else is docked, and the host can change steps, the workflows feature shall dock the step's card at the right, with the canvas beside it usable and undimmed: the step's name as its card on the canvas shows it (its title, else its id) as the title, taking focus, the breadcrumb "<workflow> › <id>", then the fields the step's kind has: **Type**, a picker of the six kinds (Agent step, Wait, End, Workflow, Parallel, For each), for every kind; **Agent**, a picker of "No agent" and the hub's agents, for an agent step and a for each step (with "No agent: this step passes the data straight on." while it has none, and an agent the file names that the hub doesn't have kept in the list by its id); **Prompt** for an agent step with an agent picked whose prompt is text (with "The agent gets the run input." while it is empty), **Save output as** for the kinds that run something (with "Later steps can pick this as step <name>." once it has one), and **Description** for every kind. A pick in Type or Agent shall be saved at once, as one change of the step, and the card shall show the fields of the kind and agent picked, a hidden field's text staying in the file; each text field shall save by itself, after a pause in typing and when it is left, as one change of the step; a field that holds a key shall not be saved, shall say "This looks like a key. Keep it as a secret instead?", read out once as it appears even while focus stays in the field, and shall count as not saved in the toolbar. When the host can't change the step, a danger toast shall say "Couldn't change step <id>" and why. When the card opens or is replaced, the canvas shall pan just enough that the picked step shows whole, left of the card, keeping the zoom; it shall not move for a step that already shows. Picking another step shall replace the card; Esc, ✕ and a click on the canvas's background (not a pan) shall close it and unselect the step; a press on the canvas's toolbar or zoom buttons, also between their buttons, is not on the background.

## Examples

- Given Support reply, when the user clicks `write`, then a card titled "write" has focus, reads "Support reply › write", and shows its prompt, "answer" under Save output as with "Later steps can pick this as step answer." and its description.
- Given `write`, then Type reads Agent step and Agent reads Reply writer, from "No agent", "Reply writer" and "Sorter"; `start` has no agent and says "No agent: this step passes the data straight on."
- Given the card of `write`, when the user picks Sorter, then `{ agent: "sorter" }` is saved at once; when they pick Wait, then `{ type: "wait" }` is saved and Agent and Prompt go from the card.
- Given the end step `done`, then its card has only Type and Description; the agent step `start` has no Prompt while it has no agent, and once Sorter is picked its empty Prompt says "The agent gets the run input."
- Given the card of `write`, when the user picks No agent, then Prompt goes from the card and only `{ agent: "" }` is saved; when they pick Reply writer again, then Prompt is back with "Answer {{input.message}}".
- Given the card of `write`, when the user changes the prompt and leaves the field, or stops typing in Save output as, then that field is saved as one change of `write`.
- Given a key pasted into Description, then it isn't saved, the card says "This looks like a key. Keep it as a secret instead?" and the toolbar counts 1 field not saved.
- Given a key typed into Prompt, when the user pauses with focus still in it, then "Prompt: This looks like a key. Keep it as a secret instead?" is read out once.
- Given the host can't change the file, then a danger toast says "Couldn't change step write" and why.
- Given the card of `write`, when the user clicks `done`, then the one card is now "done".
- Given a step `write` whose description starts "Writes the answer", then its card is titled "Writes the answer"; given a new step `step-1`, it is titled "step-1", not "Step step-1".
- Given the canvas at 200 % with `done` half hidden at its right, when the user clicks `done`, then its card opens and the canvas pans until `done` shows 16 pixels clear of the card, still at 200 %.
- Given the card of `write`, when the user presses Esc, clicks ✕ or clicks the canvas's background, then it closes and `write` isn't selected; dragging the background, or pressing the toolbar's divider or between the zoom buttons, keeps it open.
- Given a host that can't change steps, or a phone, then picking a step docks no card.
