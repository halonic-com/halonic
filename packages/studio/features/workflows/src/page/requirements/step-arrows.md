# workflows.page.step-arrows

- Status: active
- Since: unreleased
- Source: HAL-12216 (T7b, arrow editing); HAL-15202 (C548 1 and 4, never-taken arrows and step names); HAL-15540 (C592 1 and 2, the never-taken line's tone and reading); HAL-15586 (C596 4, a wait's new arrow); UX checklist 10.8 (Arrows in), 10.9 (the section, Move up and Move down); flow-workflows 4.3, 5.3; microcopy 9.4, 19.7; a11y 7.2

When a step that isn't an end has its docked card and the host can change arrows, the workflows feature shall show the section "Arrows (first match wins)": the step's arrows numbered in the file's order, each as "<n> → <step>" then "on <event>" (or "after <time>" for a timer) and "if <condition>" when it has one, with the run's data named without its braces and without `context.`; each row shall have a ⋮ named "More actions for arrow <n>" with **Move up** (unavailable on the first) and **Move down** (unavailable on the last); under them **Go to…**, a picker of the workflow's steps other than this one, and **Add**. Wherever this section names a step (a row, **Go to…**, an announcement, **Arrows in**), it shall name it as its card on the canvas does: by its title, or by its id when it has none, with the id in brackets after a title another step shares. An arrow that is never taken, because an earlier arrow on the same event has no condition (a timer is no event), shall read "△ Never taken: arrow <m> always matches first" under its row's words, in the attention tone the canvas gives the same check, and the row's button shall be described by that line, so it is read with the row. Move up and Move down shall move the arrow one place as one change, naming where the arrow goes so an out-of-date card can't move another one, and do nothing while a move is still being written; they shall keep focus on the moved arrow's ⋮ in its new place and announce "Arrow <n> is now <place>.", followed by "Arrow <k> is never taken: arrow <m> always matches first." when the move left one of the two arrows never taken. Add shall add an arrow on done to the step picked, after the others, as one change, announce "Arrow added: <step> to <target>.", followed by the same sentence when the new arrow is never taken, with the new row expanded to its fields when it is never taken or the step is a wait (whose arrow needs the answer that takes it), and clear the picker; with no step picked it shall put focus on **Go to…** and add nothing. When the host can't change the arrows, a danger toast shall say "Couldn't change step <id>" and why, and nothing is announced. Every step's card shall list **Arrows in**, "From <step>" once for each other step with an arrow to it, each opening that step's card with focus on its title.

## Examples

- Given `sort`, then its rows read "1 → approve on done if category = refund" and "2 → write on done"; `approve` reads "1 → write on approved" and "2 → done after 2d".
- Given the end step `done`, or a host that can't change arrows, then the card has no arrows section.
- Given `sort`, when the user picks ⋮ › Move up on arrow 2, then `write` is first, "Arrow 2 is now first. Arrow 2 is never taken: arrow 1 always matches first." is announced and focus is on "More actions for arrow 1".
- Given `sort`, then arrow 1's ⋮ offers Move up unavailable and Move down, and arrow 2's Move up and Move down unavailable.
- Given Move up on arrow 2 is picked twice before the first move is written, then the arrow moves once.
- Given `sort`, when the user picks `done` in Go to… and presses Add, then "3 → done on done" is added and "Arrow added: sort to done. Arrow 3 is never taken: arrow 2 always matches first." is announced; pressing Add with nothing picked puts focus on Go to….
- Given Acme's `classify` ("Classify it") with "1 → Finished without a reply on done if kind = spam" and "2 → Draft a reply on done", then Go to… offers the other steps by their titles and not "Classify it"; Move down on arrow 1 leaves row 2 reading "△ Never taken: arrow 1 always matches first", which its button is described by; adding an arrow to "Check the draft" expands row 3 and announces "Arrow added: Classify it to Check the draft. Arrow 3 is never taken: arrow 2 always matches first."
- Given `review` with arrows on approved, on rejected and after 2d, then no row says it is never taken.
- Given the wait step `approve`, when the user adds an arrow to `done`, then row 3 is expanded to its fields with **On event**.
- Given a host that can't change the file, then Add shows the toast "Couldn't change step sort" and the rows stay.
- Given `write`, then Arrows in lists "From sort" and "From approve"; pressing "From approve" opens "approve" with focus on its title.
- Given `sort` has two arrows to `write` and `write` one to itself, then Arrows in on `write` still lists "From sort" once and not "From write".
