# workflows.start.start-run

- Status: draft
- Since: unreleased
- Source: HAL-10208 (T7 PR 5b); HAL-12215 (W2, checklist 10.13); HAL-12368 (UX check L4, L5); HAL-12412 (UX check S4; C471-6 of HAL-14728); states C18, C19, C25, C26, D7, D8; HAL-13143 (C144 RT1); HAL-13100 (C131 E4); HAL-14323 (c343 X2, C471-5); HAL-14739 (C471-1, errors make Run unavailable)

When the host can start runs, the workflows feature shall show **Run** at the right of the page's header on every tab, which opens a card docked at the right, titled "Run *the workflow's name*", with the run's input as JSON and **Start run** and **Cancel**. The input starts as the first test's input with the line "Filled from the first test." under it, or as `{}` when the workflow has no test; **Start run** shall ask the host to start the workflow's run with that input and, once it has, dock the run's simple card and show a strip above the canvas that names how the run stands in the Runs row's words ("Showing run 01jd8q · failed in Draft reply", "· done", "· budget reached in …", "· cancelled in …", "· running in …", "· waiting in …"), with a button that clears it; until the runs list the new run, the dock shall say "Run started. Waiting for it to appear…" with a button that closes it; a failed run's step shall be ringed in danger with a **Failed** chip on the card's top edge at the right, which keeps the step's name in view and which a screen reader doesn't hear, since the step's status dot already says it. The run's card shall offer **Run again** and **Open Models** on a failed banner as the run page does, and **Run again** shall dock the new run's card as **Start run** does. An input that isn't a JSON object shall say so under the field and start nothing. When the start fails the card shall stay open with the input kept and say, in a danger Callout that takes focus, "Couldn't start the run: *reason*." with **Try again**, worded as the run page's **Run again** is (`shell.start-failure`): the reason lower case after the colon unless it starts with a name, and "the engine isn't answering. It may still be starting." when the host says the engine can't be reached (the words for where Studio runs). A failure Halonic can't explain shall say "Halonic ran into a problem it can't explain yet." with **Copy details** in place of **Try again**, and a reason that replaces the shell's own words, such as "Halonic can't write to its data folder.", shall have **Copy details** next to **Try again**. When the host's refusal names a next step, the step shall be the Callout's second line in place of **Try again**, except for a lock another Halonic holds (a `conflict`), which keeps **Try again** next to its step (design check C471-6); when only a terminal can start the run, the second line shall lead to the command ("To start it, run this in a terminal:") and the whole command shall follow in a CommandBox with **Copy command**. When the host refuses because the workspace isn't trusted yet (a `denied` refusal) and can open the trust check, the Callout shall offer **Review** in place of **Try again**, which opens the trust check; once the person trusts the workspace, the Callout shall go and **Start run** shall take focus. When the host already knows from the files that it would refuse the run (an agent in a harness program or one that lists a connector), **Run** shall be unavailable (it stays focusable and ignores presses) and a warning Callout band under the header, in the shape of the sandbox's (`workflows.page.cant-run`), shall say "*the workflow's name* can't run: *reason*" in its first line, then the next step, with its command in a CommandBox when it has one, in place of the start command, the first line linked to **Run** by `aria-describedby` (rule N5, under D6). While the workflow has errors, in its own file or in the file of an agent one of its steps names, **Run** shall be unavailable the same way, on desktop and phone, and the first band under the header shall say "*the workflow's name* can't run: it has *n* problems." ("1 problem" for one) with **Open Problems**, which opens Configuration on its Problems with the focus on Problems in the page list; Run shall be described by that line first and by the sandbox's first line after it when that holds too, and the files' band shall not show until the errors are fixed. Run shall be available again as soon as the last error is fixed, with no reload, and shall stay as it is until the first check of the files is in. When an edit makes errors while the card is open, the card shall show, in place of **Start run**, a danger Callout that says "*the workflow's name* has *n* problems. Fix them before it can run." ("has 1 problem. Fix it …" for one) with **Open Problems**, which closes the card, opens Configuration on its Problems and puts the focus on Problems in the page list; warnings shall not stop a run. When the host can't start runs, the page shall show no **Run**.

## Examples

- Given the workflow "Support reply" and a first test with the input `{"from": "a@example.com"}`, then the card is titled "Run Support reply", the input holds that JSON and "Filled from the first test." shows under it; when the person types, the line goes.
- Given the workflow has no test, then the input reads `{}` and no line shows.
- Given the card is open, when the person presses **Cancel**, then the card closes and nothing starts.
- Given a host that starts runs, then the header shows **Run**; given one that doesn't, it doesn't.
- Given the input `{"from": "a@example.com"}`, when the person presses **Start run**, then the host starts the workflow with that object.
- Given the engine isn't answering, then the card says "Couldn't start the run: the engine isn't answering. It may still be starting." with the input kept and **Try again**.
- Given the host fails with "The disk is full", then the card says "Couldn't start the run: the disk is full."
- Given the host fails with an error that has no kind, then the card says "Couldn't start the run: Halonic ran into a problem it can't explain yet." with **Copy details** and no **Try again**.
- Given the started run failed because Ollama wasn't running, then the run's card offers **Run again** and **Open Models** on its banner, as the run page does, and **Run again** starts the workflow with the run's input and docks the new run's card.
- Given the agent Reporter runs in Claude Code, then the card says "Couldn't start the run: Reporter runs in Claude Code, which Halonic can't start yet." and "Set Reporter to Halonic on its Harness page to run it now.", with no command and no **Try again**.
- Given the files say Reporter runs in Claude Code, then **Run** is unavailable and the band under the header says "Support reply can't run: Reporter runs in Claude Code, which Halonic can't start yet." and "Set Reporter to Halonic on its Harness page to run it now.", with no command.
- Given the files say the agent Reporter uses a connector, then **Run** is unavailable and the band under the header says "Support reply can't run: Reporter uses a connector, which Studio can't start yet." and "To start it, run this in a terminal:" with `halonic run reply`; pressing **Run** opens no card.
- Given the agent Reporter uses a connector and the start is refused after the press, then the card says "Couldn't start the run: Reporter uses a connector, which Studio can't start yet." and "To start it, run this in a terminal:" with `halonic run reply`, or `halonic run acme/reply` when another hub has a `reply`, and **Copy command**, and no **Try again**.
- Given the started run failed in `draft`, then the strip says "Showing run 01jd8q · failed in Draft" and the step `draft` is ringed with **Failed** on its top edge; its card reads "AGENT STEP draft Failed writer", with "Failed" once.
- Given the host started the run but the runs don't list it yet, then the dock says "Run started. Waiting for it to appear…", and the run's card replaces it once they do.
- Given the host refuses with "This workspace isn't trusted yet, so nothing was started." (`denied`) and can open the trust check, then the card says "Couldn't start the run: this workspace isn't trusted yet, so nothing was started." with **Review** and no **Try again**; **Review** opens the trust check.
- Given the person trusts the workspace from **Review**, then the Callout goes and **Start run** has focus.
- Given the input `[1]`, then the card says "The input has to be a JSON object, such as {}." and nothing starts.
- Given "Support reply" has one error in its own file and one in the agent Writer that a step names, and a warning, then **Run** is unavailable, described by "Support reply can't run: it has 2 problems.", and the band offers **Open Problems**; with 1 error it says "it has 1 problem."
- Given the same errors and an agent that uses a connector, then only the problems band shows; once the errors are fixed, Run is described by the connector's band instead.
- Given the same errors and a sandbox that can't start, then both bands show, the problems band first, and Run is described by both first lines in that order.
- Given the start card is open and an edit makes those errors, then the card says "Support reply has 2 problems. Fix them before it can run." with **Open Problems** and no **Start run**; **Open Problems** shows Configuration's Problems, with the focus on Problems in the page list.
- Given the workflow has only warnings, or no problems, then the card offers **Start run**.
