# halonic-action-send

The Studio shell's side of user-only action steppers (HAL-17525). Plain Rust with no Tauri types. The shell's `action_*` commands wrap it and give it the keychain, the network and the native dialogs. Design: the architecture note on HAL-17491 (sections 2.4, 3 and 7.1) and `docs/adr/2026-11-24-action-sender.md`.

An agent can only file a request. The user runs it step by step in Studio desktop, and the shell sends each step with the user's own token. So the shell sends **only** steps the catalog reviewed:

- **Route list.** Every step the shell may send or open is in a list generated from `core/action-catalog` and compiled in (`halonic.action-routes/1`). `RouteList::parse` refuses the whole list if any route can't be checked. That covers an unknown service, a path segment that isn't plain, placeholders that don't match the template, and a pattern outside the subset the shell reads (`pattern.rs`; no regex crate, so the subset fails closed).
- **A send names a step, never an address.** The page gives the definition, version, step number, one value per placeholder and the body fields. The shell refuses anything off the list (`not-in-catalog`), and any value that is missing, extra, of the wrong kind, off its pattern, empty, `.` or `..`, or holds `/`, `\`, `?`, `#` or `%` (`bad-value`). Each placeholder is one percent-encoded segment.
- **Fixed origin, no redirects.** The origin and base path come from `services.rs` (`github` → `https://api.github.com`, `cloudflare` → `https://api.cloudflare.com/client/v4`), not from the list. A route's query has fixed keys only (`?type={type}&name.exact={name}`), each value one placeholder, form-encoded, and a value holding `&` or `=` is refused. The transport follows no redirect: a `3xx` comes back as a status with no kept fields and no address.
- **Only kept fields.** A successful answer gives back only the route's `keep` fields that hold plain values. For Cloudflare the fields come from the `result` envelope, and a list answer gives its one item plus `total_count`; a list of more than one keeps nothing. A failed one gives the service's `message` (Cloudflare's `errors`, with their codes), cut to 300 characters, with the token, key shapes and long random-looking words dropped.
- **The token stays in the shell.** It is read from the keychain under `action__<service>__<account>`, goes into one `Authorization` header, and never into a result, an error, a dialog or a log line. The `action__` names are reserved in `halonic-secrets`, so the page's secret commands, the agent host and the engine can't read them.
- **Native confirmation.** `admin` steps are confirmed in the shell's own dialog, showing the account, the method, the address the shell built and the body.
- **Dialog with text fields** (HAL-18085). An `irreversible` step, or any step with a `secret-input` field, is asked for in one window that shows the same and adds the fields. An `irreversible` call route must carry `target`, a template over its own placeholders such as `{owner}/{repo}`, and no other route may. The user types the filled name, and anything but an exact match sends nothing. Each secret has a masked field. The window's page (`ask_page.rs`) is a fixed page with no script, served from the shell's own `halonic-action` scheme to that window only, and no capability names the window. Send posts the form to the same scheme, so typed values reach the shell in the request body, never in an address or the Studio page. `read_form` decodes each value into a buffer that is zeroed when dropped and zeroes the body. The body is written field by field into one buffer sized so it never grows, so no other copy of a secret is left, and the sent call wipes it. Kept fields and error text drop a secret's value as they drop the token. Closing the window or Cancel sends nothing (`cancelled`). The webview's own copy of what was typed is out of reach, as reqwest's copy of the token is; the window is destroyed straight after.
- **Pages.** `open_guided` builds a guided step's page from its route. `open_page` checks a `browser` block's address the same way as `checkBrowserAddress` in `@halonicjs/action-steppers`: `https`, no user info or port, a host on the list, no query or fragment, and a path that is decoded once, has no `.`/`..`, `//`, `\` or `%2F`, and starts with a declared prefix. Both share one limiter: the same page at most once every 3 s, and any page at most once a second.
