# halonic-host-settings

The settings kept where Halonic runs (HAL-6261): the assistant and the sandbox default, for every workspace on this computer. `FileHostSettingsStore` keeps them exactly as `FileHostSettingsStore` in `packages/adapters/fs-node` does, so the desktop app and the CLI share one file, `<profile>/settings/host.json`. Plain Rust with no Tauri types; the shell's `host_settings_*` commands wrap it.

- `read`, `set` and `remove` keep the `HostSettingsStore` port: values by key, a save changes one key and keeps every other key and field, also the ones a newer Halonic wrote. `is_host_setting_key`, `read_saved_host_settings` and `change_saved_host_settings` are ports of the TypeScript functions of the same names in `@halonicjs/ports`.
- A file that can't be parsed reads as none saved, and the first save over it keeps it as `host.json.broken`.
- A `host.json` that is a link, a hard link or not a plain file can't be read, so `read` fails as `Unreadable`; a save renames a new file over it. The open itself won't follow a link: `O_NOFOLLOW` on Unix (with `O_NONBLOCK`, so a named pipe can't make it wait), `FILE_FLAG_OPEN_REPARSE_POINT` on Windows. A hard link is refused on Unix only: Windows' standard library doesn't give a file's link count, and this crate keeps the workspace's ban on `unsafe` code.
- Writes go through a temporary file and a rename. On Windows a rename refused because another program holds the file is tried again after 10, 20, 40, 80 and 160 ms, as `renameOver` in `fs-node`. The folder gets mode `700` and the file `600`.
- The store doesn't take turns: the shell holds one lock around every save, so two windows that save two keys at once keep both.
- `serde_json` sorts the fields when it writes the file, and writes numbers in its own form: `1e3` becomes `1000.0`. The settings are the same; only the order and the number text differ from what `fs-node` writes, so a value with fractions may count a few bytes more or less against the 256 KiB than on the TypeScript side.

`tests/golden.rs` checks the golden cases, `packages/testing/contracts/src/golden/host-settings-limits.json`: the keys allowed and refused, the sizes at the limit and the saved texts, the same file the TypeScript contract suite reads. `tests/files.rs` checks the file rules. The requirement in `requirements/` is a draft until the trace check reads `cargo test` results. Until then, each test's name starts with `host_settings_file_`.
