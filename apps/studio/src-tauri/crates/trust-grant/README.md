# halonic-trust-grant

Which folder a trust grant may open in the Studio shell, and the question the shell asks first (HAL-2612, plan approved by Liam on HAL-2652). Plain Rust with no Tauri types; the shell's `pick_folder`, `reopen_folder`, `forget_folder` and `trust_*` commands wire it to the profile, the opened folders and the native dialogs.

- **Only the person opens a folder.** `TrustState::pick` opens the folder picked in the dialog. `TrustState::grant` saves a record and opens its folder only when it is inside a picked folder, or when the person says yes to the question. A folder a grant opened doesn't count as picked.
- **Locations must already be canonical,** in the plain form the CLI keys its records by (`plain_path` in `halonic-git-guard`: no `\\?\` prefix on Windows). Anything else, such as `..`, a link or a trailing separator, is refused as `invalid_record` and never rewritten, so the record's key and the opened folder are the same path and a revoke closes what the grant opened. Picked folders are compared by path part, so `work-evil` isn't inside `work`.
- **One dialog at a time.** A grant or a pick that would show a second dialog is refused as `busy`.
- **Revoking closes a folder a grant opened** before deleting the record, so git refuses it at once. A folder the person picked stays open (HAL-8576): the open workspace keeps its file access, and the pick only stops sparing a question, so the next grant asks again.
- **Picked folders survive a restart** (HAL-6637). `PickedFolders` keeps the folders the person picked in a list in the profile (`studio/picked-folders.json`), most recently picked or reopened first and at most nine; only a pick adds to it (`TrustState::pick_remembered`), and on Unix only with the folder's device and inode. `TrustState::reopen` opens one again only while it is the same canonical path and, on Unix, the same device and inode (an entry without them fails closed); otherwise it is refused as `not_picked`, `folder_missing`, `folder_changed` or `folder_unreadable`, and the entry stays. `TrustState::forget` drops an entry and closes its folder, but keeps its trust record. A list file that can't be read is an empty list, and a longer one is read capped at nine. On Windows an entry has no identity yet: the standard library has no stable call for a folder's file ID.
- **A new workspace folder** (HAL-8745). `TrustState::pick_parent` shows the folder dialog for the place a new workspace goes in and keeps the answer in memory only (at most nine per session): the parent is not opened, not picked and not remembered, so it never shows in Recent. `TrustState::create_workspace` makes `<parent>/<name>` and opens it as a pick does (opened, spares questions inside it, remembered in the picked list). The parent's real path must be the Documents folder or a parent chosen this session (`parent_not_chosen`), and not the profile or inside it (`parent_private`). The name goes through `check_workspace_name`: one plain name, the same on every platform, refused as `name_invalid` with a `reason` (`empty`, `dots`, `separator`, `too_long`, `forbidden_character`, `trailing_dot_or_space`, `reserved_name`). It uses `create_dir`, never `create_dir_all`: something already at the path is refused as `exists` and never adopted. No trust record is written; the page asks for trust as for any picked folder. `TrustState::probe_workspace` says whether `<parent>/<name>` is `new`, `empty`, `files` or `workspace` (a `workspace.yaml` is in it), after the same checks and by names only; a link or file at the path is `exists`. `TrustState::open_workspace` opens a folder that exists, as a pick, only after `ask` shows the person the trust question and they say yes (`None` when they say no, `busy` while another dialog shows); it checks again afterwards and refuses as `folder_changed` when the folder was swapped meanwhile. No trust record is written.
- **The question** (wording decided with Sofia on HAL-2653) shows the canonical path with control and text-direction characters written out as `\u{…}`, and a long path shortened in the middle.

`TrustRefusal` serialises to the shape `isTrustRefusal` in `packages/adapters/fs-tauri` reads. The requirement in `requirements/` is a draft until the trace check reads `cargo test` results. Until then, each test's name starts with `trust_grants_`.
