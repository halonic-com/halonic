# halonic-profile

Finds the profile folder exactly as `profileFolder` in `@halonicjs/profile` does, so the Studio shell and the CLI share one profile (HAL-2612). The shell uses it to find the trust folder, `ProfileFolder::trust_folder`, where both keep their trust records. It doesn't use Tauri's own app data folder, which would differ from the CLI's.

- `profile_folder(&ProfileEnvironment)`: `HALONIC_HOME` when it is set, else `%LOCALAPPDATA%\halonic` on Windows, `<home>/Library/Application Support/halonic` on macOS, `$XDG_DATA_HOME/halonic` or `<home>/.local/share/halonic` on Linux. A relative `HALONIC_HOME` or home folder is refused; a relative `LOCALAPPDATA` or `XDG_DATA_HOME` is ignored; an empty variable counts as unset.
- `ProfileFolder::workspace_folders(real_path)` (HAL-2701): a workspace's folder, `workspaces/<key>`, and `runs_folder(deployment)`, `blobs_folder()` and `records_folder()` inside it, exactly as `workspaceFolders` names them, so the shell's stores and the CLI's `FolderRunStore`, `FolderBlobStore` and `FileRecordStore` share one workspace's runs, blobs and records. The key is the first 32 hex characters of the SHA-256 of the path in one spelling, with the same steps in the same order as in TypeScript: trailing separators dropped; on Windows `/` as `\`, the verbatim prefix dropped, then lower case; on macOS NFC, then lower case. A relative workspace path, or a deployment id `deployments.yaml` refuses, is a `WorkspaceError`.
- Paths are plain text, joined the platform's way (`native_path.rs`, a port of `native-path.ts`), so they compare with the TypeScript answers character for character.
- Two dependencies, both already in the shell's `Cargo.lock` and pinned to those versions, so cargo-deny has no new crate to audit: `sha2` for the key, and `icu_normalizer` for NFC on macOS, since Rust's standard library has none (approved by Liam on HAL-2719, the same exception as `sha2` in `trust-store`).

`tests/golden.rs` checks every case in `packages/core/profile/src/golden/profile-folders.json`, the same file the TypeScript package's tests read. A change to the rules changes that file, and both sides must pass it. The requirement is `profile.trust-folder` in `packages/core/profile/requirements`; these tests' names start with `trust_folder_`.

`tests/workspace_golden.rs` does the same for `workspace-folders.json` (requirement `profile.workspace-folders`, tests named `workspace_folders_`). Its macOS cases cover a decomposed and a composed `é`, a final and an inner capital sigma, `İ` and `ß`, so a gap between V8's and ICU4X's Unicode data shows up as a failing case. Non-ASCII characters are written as `\u` escapes there, so the two forms of `é` can be told apart.
