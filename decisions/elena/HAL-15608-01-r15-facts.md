## What changes

`plugins.plugin-page-stopped`: R15 said "*Plugin* stopped: the sandbox stopped working while it ran." and "Halonic
doesn't start it again without the sandbox.", while the CLI's line for the same stop says none of it ran and the
next run tries the sandbox again. The code agrees with the CLI: the host records the stop when the fence fails as
the runner starts (`agent-host.plugin-run-state`), so none of the plugin ran, and the start gate decides every later
start as before, so the next run that uses it tries the sandbox again by itself; **Check again** only drops the note.

R15 now reads "Halonic stopped *Plugin*: the sandbox didn't work when it started, so none of it ran." with "Halonic
tries *Plugin* in the sandbox again the next time a run uses it, and never runs it without the sandbox." under it
(Sofia's words on HAL-15616). "Halonic stopped" because "*Plugin* stopped" sounds like it was running; the second
sentence starts as the toast of **Check again** (#4706) does and keeps the old promise. The Callout's place, tone,
**Check again** and its toast are unchanged. The requirement's first example names both sentences. The unreleased
changeset `plugin-page-stopped.md`, the README and comments in the host and the desktop requirement get the same
facts.

No test was weakened or skipped: the page's tests check the two new sentences where they checked the old ones.
