# Decision: the run log's `llm.request` names the model alias

- Approval: https://paperclip.halonic.com/HAL/issues/HAL-11049 (Liam approved the split of PR 6: "6c log facts and banners")
- Kind: user-visible
- Signature: ed25519:sha256:H_TEiCBwniz-xuAw0H_8Qyq9EdLD-LQUeUHvFk2fKeM:s0Hfb4/PwPNhpmhug7934doNlOHEHtIKrqg2SnOgBCxUoO7wCSXDFgGQ7i9LBz40p5USN9z1XVPM2WWe0kV+BQ==

The `llm.request` event gets an optional `alias`, so the Failed banner for a model that can't use tools can say "used by the model alias `fast`" (microcopy 15.3). New requirement `engine.llm-request-alias`. Older logs have no alias, and nothing existing changes. The old engine never wrote an alias, so the parity compare gets an allowed difference (`llm-request-names-the-alias`, rule `llm-request-alias`) that leaves it out of the new events, and the CLI run goldens show it. `allowed-differences.json` is one of the guard's own paths, so this note is `user-visible`; the CTO's key signs those on its own for paths that are not trust roots (HAL-8506).
