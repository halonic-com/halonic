# Decision: the run log's `llm.request` names the model alias

- Approval: https://paperclip.halonic.com/HAL/issues/HAL-11049 (Liam approved the split of PR 6: "6c log facts and banners")
- Kind: internal
- Signature: ed25519:sha256:H_TEiCBwniz-xuAw0H_8Qyq9EdLD-LQUeUHvFk2fKeM:f6ltRBBITYFxALmy2MF7qYDeozzj92gzQPQjR3Pk1XV0K6WTnwaWsbVPXP3dg77S0SsS9fjXe9n4NE0gO7mFCA==

The `llm.request` event gets an optional `alias`, so the Failed banner for a model that can't use tools can say "used by the model alias `fast`" (microcopy 15.3). New requirement `engine.llm-request-alias`. Older logs have no alias, and nothing existing changes. The old engine never wrote an alias, so the parity compare gets an allowed difference (`llm-request-names-the-alias`, rule `llm-request-alias`) that leaves it out of the new events, and the CLI run goldens show it.
