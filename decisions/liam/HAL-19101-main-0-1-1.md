## What changes

`main` gets `packages/core/format/spec/released/0.1.1/`, byte for byte as tag `v0.1.1` holds it
(the release branch's version commit, #5632). Six of those copies differ from `main`'s current
spec, so the guard reports them as added golden files:

- `agent.schema.json`
- `deployments.schema.json`
- `hub.schema.json`
- `models.schema.json`
- `workflow.schema.json`
- `workspace.schema.json`

## Why

0.1.1 shipped from `release/halonic-0.1.1`, cut at `3eaf040d2`, so its spec copies are the specs
as they were at the cut. Since then `main` merged spec changes the release doesn't have: opencode
as a harness (#5754), `chatUi` (#5695), `harnessLimits.maxTokens` (#5586),
`limits.scopeDailyRequests` (#5863), the Cloudflare account id (#5543), the OpenRouter host pin
(#5431), tool and rule steps (#6126, #6119) and the run token limit (#5606). Each of those went
through its own review for the current spec. A copy of `main`'s current spec under `0.1.1` would
claim 0.1.1 had them, and the API-spec check would then judge the next release against a baseline
that never shipped. So the copies have to be the shipped ones, and they can't equal `main`'s
current spec. The other copies in this pull request (format, integration kit, connect) equal the
current spec and pass without a note (`check.guard-golden-files`).

## Tests

No test was skipped, weakened or deleted. The `@halonicjs/format` tests, which compare the current
specs with the newest released copy, pass with these copies (1871 tests).
